# نوشتن یک اسکیل

این صفحه نسخهٔ بلند `skills/write-a-skill` است: آناتومی، آنچه اعتبارسنج اعمال می‌کند، و پرسش‌هایی که
مرورگر خواهد پرسید.

## آناتومی

```
skills/<name>/
├─ SKILL.md
└─ references/
   └─ <topic>.md
```

`SKILL.md` یک صفحه است. اگر دو صفحه می‌شود، صفحهٔ دوم یک مرجع است.

### Frontmatter

```markdown
---
name: debug-connectivity
description: Diagnose why two processes, two machines, a container and its host, or a client and a
  server cannot exchange traffic. Use when a connection times out or is refused…
license: MIT
---
```

| فیلد | قاعده | دلیل |
| --- | --- | --- |
| `name` | kebab-case، دقیقاً مثل نام پوشه | ناهم‌خوانی یعنی بارگذار اسکیل را پیدا نمی‌کند |
| `description` | ۶۰ تا ۶۰۰ کاراکتر، اول نشانه‌ها | کل محرک همین است؛ تطبیق داده می‌شود نه خوانده |
| `license` | شناسهٔ SPDX | اسکیل بین عامل‌ها کپی می‌شود؛ لایسنس همراهش می‌رود |

توضیح، تنها بخشی است که عامل قبل از تصمیم بارگذاری می‌خواند. آن را مثل جمله‌ای بنویسید که کاربر
هول‌زده تایپ می‌کند، بعد یک جمله دربارهٔ این‌که کِی صدق می‌کند:

> «وقتی دو ماشین نمی‌توانند حرف بزنند، وقتی timeout یا refusal می‌آید، وقتی سرویس محلی کار می‌کند
> ولی از هاست دیگر نه…»

نه: «این اسکیل تشخیص شبکه شامل TCP/IP را پوشش می‌دهد.»

### بخش‌های بدنه

| بخش | کار | اعمال‌شده |
| --- | --- | --- |
| پاراگراف مقدمه | بدون این اسکیل چه چیزی خراب می‌شود | — |
| `## When to use` | جزئیات محرک، و صراحتاً کارهایی که نباید | در صورت نبود، هشدار |
| `## Ground rules` | ۴ تا ۷ قاعدهٔ شماره‌دار و قابل بررسی | — |
| `## Procedure` | گام‌های شماره‌دار، هر گام یک اقدام | — |
| `## Anti-patterns` | جدول: حرکت وسوسه‌انگیز ← چرا غلط است | — |
| `## Definition of done` | چک‌باکس‌ها، شامل آنچه بررسی‌شدنی نیست | اجباری |
| `## Report format` | اسکلتی که عامل پر می‌کند | — |

حداقل چهار سرتیتر سطح دو لازم است؛ اسکیلی که کمتر دارد یک یادداشت است، نه یک رویه.

### مرجع‌ها

هر چیزی که «جست‌وجو می‌شود» نه «حفظ می‌شود» را بیرون ببرید: جدول دستورها به تفکیک سیستم‌عامل، قالب‌ها،
واژه‌نامه‌ها، مثال‌های واقعی. آن‌ها را همان‌جایی از رویه که لازم می‌شوند، با نام لینک کنید:

```markdown
مجموعهٔ دستورها به تفکیک سیستم‌عامل در [references/layered-checks.md](references/layered-checks.md) است.
```

اعتبارسنج هم روی مرجعی که لینک شده ولی نیست شکست می‌خورد، **هم** روی فایلی که هست ولی هیچ‌جا لینک
نشده. هر دو پوسیدگی‌اند: اولی می‌شکند، دومی بدون این‌که خوانده شود رشد می‌کند.

## اعتبارسنج چه چیزی را بررسی می‌کند

```bash
npm run validate     # scripts/validate-skills.mjs --check
```

| بررسی | حالتی که جلویش را می‌گیرد |
| --- | --- |
| frontmatter موجود و بسته | بارگذار بی‌صدا اسکیل را رد می‌کند |
| `name` با پوشه یکی است | اسکیلِ پیدا‌نشدنی |
| توضیح بین ۶۰ و ۶۰۰ کاراکتر | کوتاه‌تر از آن‌که محرک باشد؛ بلندتر از آن‌که خوانده شود |
| حداقل ۴ سرتیتر و وجود «تعریف انجام‌شدن» | مقاله به‌جای رویه |
| نبود `TODO`، `TBD`، `FIXME` | اسکیلی که قبل از تمام شدن منتشر شده |
| وجود هر مرجع لینک‌شده | اشاره‌گر مرده در لحظهٔ نیاز |
| لینک بودن هر فایل مرجع | وزن مرده |
| حجم `SKILL.md` زیر ۲۰ کیلوبایت | جزئیات بی‌صدا به بدنه برگشته |
| هم‌خوانی `catalog.json` با پوشه‌ها | فهرست ماشین‌خوانی که دربارهٔ بسته دروغ می‌گوید |

سبک اعمال نمی‌شود، قضاوت هم نه. همین نکته است: ماشین چیزهایی را بررسی می‌کند که ماشین می‌تواند،
و مرور انسانی تصمیم می‌گیرد که آیا اسکیل رفتار را عوض می‌کند یا نه.

## پرسش‌های بازبینی

در پول‌ریکوئست جواب بدهید؛ شش «بله» یا کمتر یعنی آماده نیست.

1. چه شکست مشخصی را جلوگیری می‌کند و سه نمونهٔ واقعی‌اش چیست؟
2. آیا توضیح از نشانه‌های کاربر استفاده می‌کند نه نام ماژول؟
3. آیا واقعیت‌ها (عدد، دستور، متن خطا) نوشته شده‌اند تا عامل آن‌ها را از خودش نسازد؟
4. آیا هر قاعدهٔ اصلی قابل بررسی است؟
5. آیا هر گام رویه یک اقدام دارد؟
6. آیا میان‌برِ وسوسه‌انگیز در Anti-patterns نام برده شده؟
7. آیا تعریف انجام‌شدن شامل آنچه بررسی‌شدنی نیست هست؟
8. آیا بدنه به‌قدری کوتاه است که قبل از عمل خوانده شود؟
9. آیا مرز نوشته شده — کِی نباید استفاده شود و جایگزینش چیست؟
10. آیا با و بدون اسکیل روی یک وظیفهٔ واقعی تست شده؟

## تست یک تغییر

```bash
npm test             # اعتبارسنج + همهٔ لینک‌های نسبی در همهٔ فایل‌های مارک‌داون
npm run catalog      # بعد از افزودن، تغییر نام یا حذف یک اسکیل
```

`npm run catalog` فایل `catalog.json` را بازمی‌نویسد و CI اگر فراموش کنید شکست می‌خورد. عمدی است:
کاتالوگی که دستی به‌روز می‌شود، تا هفتهٔ دوم غلط است.

## قاعده‌های دوزبانه

اسکیل‌ها به انگلیسی نوشته می‌شوند. مستندات خود بسته دوزبانه است و همان قاعده‌ها بر آن حاکم است: نام
فایل‌های آینه‌ای، دستورهایی که هرگز ترجمه نمی‌شوند، و صفحه‌ای که در یک زبان هست و در زبان دیگر نیست
یک باگ است نه یک کار عقب‌افتاده. اگر صفحه‌ای اضافه کردید، هر دو را اضافه کنید، یا در پول‌ریکوئست
بگویید کدام سمت مانده و چه کسی تمامش می‌کند.
